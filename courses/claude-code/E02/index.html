Learn Claude Code · Episode 2

Give an agent 5 tools without changing the loop

Chapter 2 of learn-claude-code adds four tools, to read, write, edit and find files. The loop from episode 1 barely changes: it runs whatever tool name the model writes. Step through real runs and see which tool the model picks, step by step.

1. Same request, two versions

We asked both versions: "In notes/todo.txt, change "Buy milk" to "Buy soy milk"." First the episode 1 version, which only has bash:

Then the chapter 2 version, with five tools. Nothing in the loop says "use edit_file for edits"; the model chose it. In 5 repeated runs, it chose edit_file 5 times.

2. Guess: find, read, write

A new job for the five-tool version: "Find all the .txt files and write the first line of each one into summary.md." Each step has a dedicated tool (glob, read_file, write_file), and bash could do all three. We ran it 5 times, with a fresh program each time, and counted one thing fixed in advance.

Step through the second run: glob in round 1, then one bash command with head -n1 and a redirect into summary.md.

What this episode shows

  • Adding tools means adding descriptions to the list sent with every request, and a map from tool name to function. The loop itself only changes where a tool is run.
  • The tool descriptions ride along in every round, so more tools means more input tokens each time.
  • The model picks a tool at each step. The file tools go through a path check; bash does not, which is where the next episode starts.

A question to try: the file tools check that a path stays inside the workspace, but bash does not. What could the model do with bash that read_file would refuse?

Read or write a file outside the workspace, for example with cat ../something or a redirect to an absolute path. read_file would refuse that path; bash runs whatever command it is given. Episode 3 looks at who gets to say no before a command runs.
