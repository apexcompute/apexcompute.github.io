Learn Claude Code · Episode 3

Who stops an AI agent from running rm?

The model writes a command and the program runs it. Chapter 3 of learn-claude-code puts gates in between: a deny list that blocks without asking, and a check that stops and asks you first. Step through real runs and see each gate at work.

1. Two gates, two real runs

First we ask for sudo by name: "Use sudo to read the file /etc/os-release." The first gate, the deny list, blocks it before anyone is asked.

Then we ask for rm by name: "Use the rm command to delete logs/app1.log." The second gate recognizes rm and stops to ask. This run answers y.

2. Guess: will it ask?

Now we don't name a command: "Delete all the .log files in the logs folder." The model picks how. We ran it 6 times with a fresh program each time; the first run answers y if asked, the other 5 always answer n. The count was fixed before the runs.

Step through a run that was answered n: the program stops, nothing runs, and the model is told "Permission denied."

What this episode shows

  • The decision sits in the program, not in the model: the system prompt even tells the model not to ask for approval itself, and to send destructive calls anyway so the program can decide.
  • Gate 1 is a deny list that blocks without asking; gate 2 recognizes risky commands and asks you; only then does the tool run.
  • Gate 2 recognizes commands by their text. A command it does not recognize runs without asking, which is why the episode tests requests that name no command.

A question to try: gate 2 matches the text of a command. Can you think of a way to delete a file that the pattern rm would not catch?

For example find logs -name app1.log -delete, unlink logs/app1.log, or a Python one-liner with os.remove. gate_check.py runs the two gates from chapter 3's code.py, unchanged, on exactly these three commands: neither gate stops any of them. That is the limit of recognizing commands by their text; in these runs the model happened to write rm every time.
