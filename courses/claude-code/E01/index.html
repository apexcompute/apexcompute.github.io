Learn Claude Code · Episode 1

30 lines that turn a chatbot into an agent

A chat model can only write text. A loop of about 30 lines, with one bash tool, gets it to read files and run commands. Step through a real run and see exactly what goes to the model each round and what comes back.

1. Step through a real run

We asked: "How many .txt files are in the notes folder? How many lines does each one have?" This is the recorded run from the episode, with chapter s01 of learn-claude-code unchanged and Claude Sonnet 5.5. Click through it one step at a time.

Two things to notice. The model never runs anything: it only replies with a tool_use block, and the loop runs the command. And each round sends the whole conversation again, so the input grows from round to round.

2. Guess: will it call bash?

The system prompt says "Use bash to solve tasks." Now we only ask an arithmetic question. We ran it 5 times.

What this episode shows

  • A tool is a description sent with every request: a name, what it does, and its inputs. The model asks for it; the loop runs it.
  • The loop is short: send the messages, look at stop_reason, run any tool_use, append the result, go round again.
  • Every round resends the whole conversation, which is why long sessions get slower and more expensive.

Run it yourself, for free

A question to try: in example 4 the model packs several steps into one bash command. Why might that be cheaper than one command per round?

Every round resends the whole conversation. Fewer rounds means the long history is sent fewer times, so one bigger command saves input tokens. The cost is that one long output can get cut off on screen, although the model still receives it in full.
