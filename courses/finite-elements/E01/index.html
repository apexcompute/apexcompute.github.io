Finite Elements from Scratch · Episode 1

Change one spring: which cells of K change?

Three springs in a chain, a wall on the left, 60 N pulling on the right. Every finite element program ends up solving K u = f. Here you build that K yourself, one spring at a time.

1. Guess first

The springs are 30, 20 and 60 N/mm. The whole chain has one 4×4 table K: row i is the force at node i, column j multiplies how far node j moves. Now the middle spring becomes twice as stiff, 20 → 40, and nothing else changes. Which cells of K change?

2. Build K one spring at a time

Each spring has its own 2×2 table, [k, −k; −k, k]. Assembly adds it into the big table where its two node numbers cross. Step through it, and watch the cells that collect two springs.

Row 2 is the force balance at node 2: −30 u1 + 50 u2 − 20 u3 = 0. The 50 is 30 from the first spring plus 20 from the second, because node 2 touches both. Put the four rows together and you get K u = f, with f = (R1, 0, 0, 60), where R1 is the wall's force.

3. Play with the stiffness

Node 1 is pinned to the wall, so we cross out row 1 and column 1 and solve the remaining 3×3. Move the sliders: the table changes only where a spring's own nodes cross, while the displacements can change all along the chain. Try k3 = 0.

What this episode shows

  • Each spring gives a 2×2 table; force balance at every node adds them into one big table K. That step is assembly.
  • K alone cannot be solved: the whole chain can slide without any force. Pinning one node fixes that.
  • Changing one spring changes exactly four cells of K, where its two nodes cross; the solved displacements can still change everywhere downstream.

Run it yourself

One script with NumPy only. It prints the table after every spring, solves the chain, checks it by hand, and lists the cells that changed.

python3 springs_e01.py
python3 springs_e01.py --k 30 20 0     # cut the third spring

Code and README on GitHub

Before you run the second line: which cells become 0, and can you still solve it?

Cells (3,4), (4,3) and (4,4) become 0, and (3,3) keeps only the 20 from the second spring. The row for node 4 becomes "0 = 60": node 4 is cut off, nothing holds the 60 N pulling it, so there is no solution. Pinning node 1 holds only the part still connected to the wall.
